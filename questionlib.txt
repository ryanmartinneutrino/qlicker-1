
We are going to introduce the question library, focusing on the prof side. This somewhat replicates the Question Library from the meteorjs version of the app, but we rethinking it from the ground up. 

Considerations:
- It should be easy for profs and students to search for relevant questions, by topic (through tags), and content. The question editor will need a place to enter tags for a question, similar to the implementation in the meteorjs version of the app. These are already stored in the legacy db. 

- Questions are associated to a course when they are created, but can easily be copied to other courses by those that are instructors in the two courses (copy from and copy to). Questions should always belong to a course. Questions should have a creator which is the original person that made that question. When questions are copied, they should retain the original creator and the id of the original question from which they were originally copied (so if a question has an id corresponding to the original question, that id should get passed down to all the "decendants"). Questions have an owner, the person that created that instance in the database. If they create an original question, they are the creator and owner of that question. If some other instructor makes a copy, the other instructor is the owner of the copy, but the original instructor is still the creator of the copy. If the question is created by a student, there is a property to indicate so. They student is the creator, but if an instructor approves the question, they automatically become the owner. Any instructor can edit a question in the course. As soon as someone edits a question, they become the owner, and the last edit time is recorded.

- There should be a new tab in the course manage page for the "Question Library". In the tab, there is a search interface to filter questions, and a list of questions shown in the same way as in the list of questions of the session editor (reuse the component and look). Add controls at the top to limit the number of questions displayed, similar to the pagination in a table, make 10 the default, but changeable. 

- In general, the questions that show up in the list of questions can be edited, so they show up as they do in the session editor, with the same controls and look (e.g. expandable and editable). 

- In the displayed list of questions, there should be a chip on a question to indicate if it belongs to a session (with the session name), since questions can belong to a course without being in a session. If the question is in a session and has responses associated to it, add a red chip that says "has responses". If the question has responses, it can only be edited in limited ways, in the same fashion as questions with responses in the session editor (their type cannot be changed, the number of options can't be changed but their content and which one is correct can still be changed, a numerical answer and tolerance can still be changed).

- The search area for the questions should filter the questions shown in the the list and have the following options:
  - Course (a dropdown of courses, searchable, that the user is an instructor in). This allows the prof to search a different course for questions to copy them over. The course chosen here is used in the query for questions in the database. Ensure that there is an index to make this search efficient. Default is current course. 
  - Type. Dropdown. Default is "All", allows search to filter for type of question (MC, TF, etc). Make sure not to hardcode the types in case we add new types of questions.
  - Tag. A textbox/dropdown to type tags in, it should autocomplete and add to a list of selected tags that are used to filter questions.
  - Session. A button that opens a small modal that lists all sessions in the course with checkboxes. The list is searchable, there is an "All" checkbox at the top. It starts with everything unchecked which corresponds to questions not being filtered by session. Otherwise, it's the list of questions is filtered to be those inside the selected sessions. The 'All' checkmark selects only sessions that have been searched in the search box if applicable. This modal should reuse the session selector modal that is used in the grade tab (to show grads and to download CSV), since it already has this functionality.
  - Content: A search box for text, it should filter the questions by their question text and the option text (for MC/MS). 
  - Approved: A control to filter questions whether they have the approved property set. Any question that is created by an instructor of the course (either in the session editor or in the question library) is automatically approved and should have the property set in the question editor. 

- The question list should show most recent questions first. 

- In the list of questions, we need to add a control to each of the questions (and this can be replicated back to the session editor). Add a copy symbol, located just above the delete garbage can. Clicking it opens a modal with the choices to:
 - Copy here: (a copy of the question is inserted right after the current question in the session's list of questions). This can only happen within the session editor. The question editor then opens directly on that question and comes in focus for the user.
 - Copy to session: A modal opens with a searchable list of courses for which the user is an instructor. When the user clicks on a course, it opens another modal, to select a session from that course into which to copy the question. The session is selected from a searchable list, but the user can also choose to copy to that course without selecting a session. 

- If the question is not approved, add a control to approve it. 

- The questions in the list should have a checkbox that allows them to be selected. In the session editor, they do not need a checkbox, so this is different here! There should be an option to also select all filtered questions. There should be several bulk operations available to the selected questions:
  - Copy to session (opens a modal where user chooses a course, default is the current course, then a session in the selected course and all filtered questions are copied there). This is exactly the same modal logic as "Copy to session" applied to a single question.
  - Delete (user gets warning). Cannot delete questions that have responses attached (this should be enforced in the backend)
